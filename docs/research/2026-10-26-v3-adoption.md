## 0. The constraint in front of three levers: PHPUnit 12+

Gesso requires `phpunit/phpunit ^12.0 || ^13.0` at runtime (`composer.json:12`). The install
probe reproduced Composer exit 2 on the stock Laravel 12 skeleton (`phpunit ^11.5.50`). A
Spectator or kirschbaum user following a migration guide, a Scramble user, and a Boost user
all land on a Laravel install, so they hit this before any trait rename.

Facts checked today:

- The `laravel/laravel` **13.x** skeleton ships `phpunit/phpunit ^12.5.12`. New Laravel 13 apps
  install Gesso without a conflict. Only Laravel 12 apps that kept PHPUnit 11 are blocked.
- Spectator's `phpunit ^11.0` is in **require-dev**, so it does not pin its users. Its coverage
  extension targets PHPUnit 11 (how many of its users are still on 11 is unmeasured).
- PHPUnit 11 stopped receiving bug fixes on 2026-02-06 (ADR 0001).

**Decision: (c) keep the ADR 0001 policy and make "upgrade PHPUnit" step 0 of every migration
and recipe page.** Options (a) and (b) were rejected for now:

- (a) Moving PHPUnit to `require-dev` and guarding the extension and subscriber classes does
  not remove the problem. The extension, the coverage gates and the assertion traits are the
  product, so a PHPUnit-free install leaves only the core validator, which is league's niche.
  It would also reopen ADR 0001 and add a lane to the matrix.
- (b) Widening the range to `^11` means supporting a runner that no longer gets bug fixes, and
  it also reopens ADR 0001.

**Revisit trigger.** Reopen ADR 0001 explicitly, not as a side effect of a feature PR, if
either of these happens:

- At least 3 distinct issues or discussions say "cannot upgrade PHPUnit 11" within one quarter.
- Otherwise, close the question at the Laravel 12 security EOL. After that date the blocked
  population is unsupported upstream, so the decision stays (c).

**Step 0 text (shared by every page):**

```bash
composer require --dev "studio-design/gesso:^3.0" "phpunit/phpunit:^12.5" --with-all-dependencies
```

Add one sentence after the command: Laravel 13 apps already satisfy this; Laravel 12 apps on
PHPUnit 11 / Pest 3 must move to PHPUnit 12 / Pest 4 first.

## 1. Migration from league / osteel / kirschbaum / Spectator

### Decision: guide plus sed/grep table, one small gap-filler method, no compatibility layer

A drop-in layer (for example, classes or traits that copy competitors' names) is **rejected**:

- **The semantics don't map.** League's API is built on in-memory specs (`fromYaml(string)`,
  `fromSchema(cebe\OpenApi)`), `OperationAddress` objects, an exception hierarchy, PSR-6 cache
  injection and PSR-15 middleware. Gesso is named-spec, file-based, result-object and
  test-time only. A shim either lies about behavior or grows into a second public API.
- **Maintenance cost.** Every shim symbol becomes a v1.x-style compatibility surface
  (`docs/versioning.md`) that is bound to someone else's release cadence.
- **Branding risk.** A class named `ValidatesOpenApiSpec` or a macro named
  `assertValidResponse` in `Studio\Gesso` reads as an affiliation or fork claim.
- **Low cost to rewrite.** The migrated code is test code, mostly mechanical, and the guide's
  incremental path (one class at a time) already exists in
  `docs/migration/from-other-validators.md`.
- **kirschbaum already lines up.** `withoutValidation()`, `withoutRequestValidation()`,
  `withoutResponseValidation()` and `skipResponseCode()` already share names and per-request
  semantics with `Laravel\ValidatesOpenApiSchema`.

`gesso migrate` (a code rewriter) is also rejected. A sed table, a grep for the leftovers and
the snippet test below give 90% of the value. A rewriter would need a PHP parser dependency
for test-only code.

**The one build item: `Symfony\OpenApiAssertions::assertResponseForOperationMatchesOpenApiSchema()`.**
osteel's `validate($response, '/users', 'post')` validates a response with no Request object.
The Symfony trait's `assertResponseMatchesOpenApiSchema(Request $request, Response $response, array $extra = [])`
requires a Request. The PSR-7 trait already has the operation-addressed form, so add the same
form to the Symfony trait (§PR-B).

The Laravel trait already accepts `?HttpMethod $method, ?string $path` overrides, so Laravel
users of osteel (wrapping `$response->baseResponse`) need nothing new.

Rewrite `docs/migration/from-other-validators.md` into four sections. Each section has these
parts:

2. A config mapping into `gesso.php`. Use v3 keys only; the phpunit.xml parameters were

Keep the existing "incremental, one class at a time" intro. Never put both validators' traits

still open. 0.19 shipped 3.1 document parsing (PR #185), and thread commenters (not the

```bash
sed -i -E \
  -e 's#self::assertTrue\((\$[a-zA-Z_]+->(validate|get|post|put|patch|delete)\(.*\))\);#\1;#' \
  -e 's#\$[a-zA-Z_]+->validate\((\$[a-zA-Z_]+), *([^,]+), *'"'"'([a-z]+)'"'"'\)#$this->assertResponseForOperationMatchesOpenApiSchema('"'"'\3'"'"', \2, \1)#' \
```

The second expression assumes that `$x` is a Response. Request validations show up in the
grep, and the guide says so.

**Method case.** `OpenApiOperationResolver` already lower-cases fixed HTTP methods, so `'post'` works. PR-B's new method uppercases fixed methods before recording coverage, matching what the PSR-7 path records; pin that in its test. OpenAPI 3.2 `additionalOperations` stay case-sensitive. No `strtoupper()` lands in user code.

**Path semantics.** osteel's `$path` is the **spec template** (`/users/{id}`), and Gesso's
operation-addressed methods take a request path. PR-A's snippet test pins whether a literal
template matches its own template. If it does not, the guide tells users to pass a concrete
path, and the sed table drops the second expression.

#### hotmeteor/spectator

The difference is structural. `$response->assertValidResponse(201)` is a `TestResponse` method
that also asserts the status code, while Gesso's assertion is a test-case method with no
status argument. Under Gesso's **auto mode** the rewrite becomes mechanical:
`laravel.auto_assert` and `laravel.auto_validate_request` validate every exchange, so
Spectator's assertions collapse into a plain status assertion or into nothing.

**Decision: no `TestResponse` macro in v3.0.** Auto mode plus sed covers the common forms. A
macro would need a static "current test case" registry, because `TestResponse` holds no test
reference, and that is an extra lifecycle seam to maintain. Revisit if users ask for it. If it
is ever built, give it a generic name (not `assertValidResponse`).

## 3. Public correctness comparison

### What already exists

`docs/conformance.md` self-reports the JSON Schema Test Suite conversion delta: 11 changed
verdicts out of 3,784 cases, each with a reason. It also covers OAI example documents. Both
corpora are pinned by SHA.

### Decision: build a measured, reproducible comparison against league only

Self-report alone does not answer a league user's real question: does 3.1 actually work there?
Comparative claims need a run, not a reading.

- **Corpus.** Reuse the already-pinned JSON Schema Test Suite `draft2020-12` files (the 3.1
  dialect). Wrap each case as a minimal OpenAPI 3.1 document: one `GET /probe` with a `200`
  `application/json` response whose schema is the case schema, and use the case `data` as the
  response body. Drive **both** libraries through their public PSR-7 response APIs:
  league `getResponseValidator()->validate(new OperationAddress('/probe', 'get'), $res)` and
  Gesso `validateResponseForOperation('GET', '/probe', $res)`.
- **Rebase references (blocking detail).** Once a case schema is embedded under
  `paths./probe.get.responses.200.content.application/json.schema`, the suite's
  `#/$defs/...` and `#` references resolve against the OpenAPI root, not the case root. Both
  libraries would then fail them identically, which measures the harness, not the validators.
  The harness therefore hoists the case schema to `components.schemas.Case`, points the
  response at `{"$ref": "#/components/schemas/Case"}`, and rewrites the case's internal `#/…`
  pointers to `#/components/schemas/Case/…`.
- **Exclusions.** Any case that still depends on `$id`, `$anchor` or `$dynamicRef` base-URI
  semantics after rebasing is excluded for **both** libraries, and the reason is recorded in
  the output. Also exclude remote refs and the optional `format` files. Start from the
  existing inclusion logic in `tests/Integration/Conformance/JsonSchemaConversionDeltaTest.php`
  (the 3,784-of-3,824 selection and its `excluded_groups`) so the published number can be
  compared with `conformance.md`, and report how many cases the extra rebase exclusions
  remove.
- **Not measured.**
  - kirschbaum and osteel delegate to league (per their composer.json), so they get a single
    line saying so, not a separate run.
  - Spectator uses `cebe/php-openapi` plus `opis/json-schema ^2.3`, the same schema engine
    family as Gesso, and has no standalone PSR-7 API. Mark it "not measured", not "fails".
- **Location.** Keep it out of Gesso's dependency graph. Put it in `benchmarks/correctness/`
  with its own `composer.json` that requires the pinned `league/openapi-psr7-validator` version
  plus Gesso via a path repository. `benchmarks/` is already export-ignored.
- **Output.** The harness writes `docs/benchmarks/correctness-league.json`, keyed by suite
  file, with pass, fail and error counts per library plus versions, suite SHA and run date.
- **CI.** Add `.github/workflows/correctness-comparison.yml` with `workflow_dispatch` and a
  quarterly schedule. It is **not** a required check: a competitor's release must not break
  Gesso CI.
- **Docs.** Add a section "Measured against league/openapi-psr7-validator" to
  `docs/conformance.md` with a per-keyword table generated from the JSON, plus one README row
  ("JSON Schema 2020-12 suite, measured") with the date and pinned versions.
- **Fairness rules,** stated on the page:
  - public API only;
  - the harness is linked;
  - "error" (an exception type that is neither a validation failure nor success) is shown
    separately from "wrong verdict";
  - Gesso's own 11 deliberate deltas are shown in the same table;
  - corrections are invited via issue.

Effort: **M**.

## 4. Symfony / API Platform

Facts checked today:

- `ApiPlatform\Test\Client` is `final class Client implements HttpClientInterface` and wraps a
  `KernelBrowser`.
- `getKernelBrowser()` exists but is marked **`@internal`**.
- `ApiTestCase`'s `assertMatchesResourceItemJsonSchema` and
  `assertMatchesResourceCollectionJsonSchema` validate against the JSON Schema that API
  Platform generates from resource metadata, not against an exported OpenAPI document. They
  do not check status codes, headers or error responses against the document.
- Gesso's `assertClientMatchesOpenApiSchema(HttpKernelBrowser $client)` therefore cannot
  accept API Platform's client.

### Decision: build automatic exchange validation that works below the client

The tool works at the kernel level, so it covers `KernelBrowser`, `HttpKernelBrowser` and API
Platform's `Client` without touching `@internal` API.

**New public API:**

```php
// config/bundles.php (test env only)
Studio\Gesso\Symfony\GessoBundle::class => ['test' => true],

// test class
use Studio\Gesso\Symfony\ValidatesOpenApiExchanges;

final class BookTest extends ApiTestCase
{
    use ValidatesOpenApiExchanges; // uses OpenApiAssertions
}
```

**Behavior:**

- `GessoBundle` registers an internal `kernel.response` listener. It records
  `(Request, Response)` for **main requests only** in a process-static recorder, and records
  only in the `test` environment.
- `ValidatesOpenApiExchanges` adds a `#[Before]` method that clears the recorder and an
  `#[After]` method that drains it. For each recorded exchange, the `#[After]` method calls
  `assertRequestMatchesOpenApiSchema($req, $status)` and then
  `assertResponseMatchesOpenApiSchema($req, $res)`. Coverage, dedupe and baselines are reused
  as they are.
- Using the trait is the opt-in. There is no new config key, mirroring kirschbaum's
  "trait = auto" ergonomics.
- `#[SkipOpenApi]` (the existing framework-neutral attribute in `src/Attribute/`) opts out a
  test.
- A `withoutOpenApiValidation()` per-next-request flag is **not** added in v1 of the feature
  (YAGNI). `#[SkipOpenApi]` covers it.
- A streamed response fails with the existing "buffered responses" message.
- The bundle missing while the trait is used is a **loud** failure: "GessoBundle is not
  registered for the test environment". It must not silently validate nothing.
- Process-isolated or insulated clients (`$client->insulate()`) are out of scope and
  documented as such.

**Files:**

- `src/Symfony/GessoBundle.php`
- `src/Symfony/ValidatesOpenApiExchanges.php`
- `src/Internal/Symfony/ExchangeRecorder.php` (`@internal`)
- tests:
  - `tests/Integration/Symfony/ValidatesOpenApiExchangesTest.php`: a tiny `HttpKernel` app via
    `HttpKernelBrowser`, covering pass, fail, skip attribute, the loud failure when the bundle
    is missing, and sub-request exclusion;
  - `tests/Unit/Symfony/ExchangeRecorderTest.php`.
- docs:
  - a new `docs/recipes/api-platform.md`: export with
    `bin/console api:openapi:export --output=openapi/api.json`, run `gesso doctor`, register
    the bundle, use the trait. One paragraph contrasts this factually with
    `assertMatchesResourceItemJsonSchema` (generated schema vs exported document). It is
    complementary, not a replacement;
  - a section in `docs/contract-testing-symfony.md`;
  - a sidebar entry in `docs/.vitepress/config.mts`.
- `composer.json` `suggest`: mention `GessoBundle` under `symfony/http-kernel`. The bundle
  class needs only `http-kernel`; do not add `framework-bundle` to require-dev unless the
  integration test proves it necessary.

**Risk.** PHPUnit's `#[After]` on trait methods works in PHPUnit 12 and 13. Pin this with the
integration test.

Keep it at about 120 lines or fewer. The content comes from #511's measured failure points,

  `assertValidResponse`, `Spectator*`). Every competitor claim is version-pinned, dated and
  linked to source, as the README matrix already is. Re-check quarterly per the
  `docs/versioning.md` release checklist.

  semantics need verification in PR-A. Issue references from the brief (osteel #44 closed "no
  bandwidth", #59 viability questions) **must not** appear in docs. They are opinions about
  another project's maintenance, so cite technical scope only.
- **Comparison fairness (D).** A harness bug that makes league look worse is reputational
  damage. Mitigate with the public harness, the separate error column, Gesso's own deltas in
  the same table, and an invitation to correct.
- **Auto mode surprises (A, C).** Migrated suites will see failures that the old tool never
  asserted. The guides lead with `baseline.violations`.
- **Lifecycle seam (C).** The process-static recorder must be cleared in `#[Before]`, and the
  tests must reset it (AGENTS.md: do not let test order carry state).
- **PHPUnit gate.** The position stays as is until the revisit trigger fires. Do not silently
  widen `composer.json` in any of these PRs.
