# v3 research: vision and scope (2026-11-01)

Inputs: four research passes run on 2026-10-31 (competitor pain points, the
cross-language feature frontier, migration tooling, agent-first DX), plus the
2026-10-26 research set in this directory.

## Positioning

The out-of-process contract tools are dying (Dredd, Optic archived 2026-01,
Akita CLI). The in-process ones (Schemathesis pytest, committee, openapi-core)
are growing. The PHP field is old: league/osteel/kirschbaum depend on
cebe/php-openapi, which has no real 3.1 support. Spectator is the fastest
growing (about 4.9x in a year) and rides the Scramble wave (about 6x).

Gesso v2.9 already fixes the top switching triggers users report: 3.1
validation, `nullable`, all errors instead of first, extra response fields
without editing the spec, separate request/response toggles, and no abandoned
dependencies. v3 must (1) make that visible and provable, (2) ship features
no tool in any language does in-process, and (3) remove every reason not to
switch.

Tagline candidates: "Secure by contract", "Never break a client",
"Know what your tests prove", "Built for agents".

## Pillar 2: close the remaining gaps

- G-a Parameter styles: `deepObject`, `matrix`/`label`, cookie params, `content` params, repeated keys without `[]` (league #2, open since 2019). Verdict-changing, so v3 only.
- G-b `servers` URL prefix: automatic match against `servers[].url` paths, with `strip_prefixes` as the override (Spectator #88, kirschbaum #13, league #240). Needs an ADR 0006 amendment.
- G-c Performance: land perf A and C, publish a reproducible benchmark against league/osteel/Spectator (kirschbaum #14 "Insanely Slow").
- G-d Public correctness comparison page (adoption research §3): the same fixture corpus run through every PHP validator.

## Pillar 3: switching is trivial

- M1 `gesso config:migrate` (+ `php artisan gesso:config-migrate`): reads phpunit.xml / Laravel config, writes `gesso.php`, lists legacy flags/env vars; `--check` exits 1 while legacy keys or a competitor package remain. Also shipped on `2.x` as 2.10.0 so v2 users migrate before upgrading.
- M2 Competitor detection in `config:migrate`: detects Spectator / kirschbaum / osteel / league in composer.json and prints a file-by-file migration plan (exact edits), translating their config (for example Spectator `path_prefix` → `spec.strip_prefixes`).
- M6 Rector set (decision 5): `vendor/bin/rector process --config vendor/studio-design/gesso/rector/migrate-from-<competitor>.php`, plus a v2 → v3 set.
- M3 Per-competitor guides with sed recipes, each pinned by a CI test (`MigrationGuideTest`) that runs the recipe on a fixture project.
- M4 PHPUnit 11 / Pest 3 stay unsupported (decision 3); `config:migrate --check` flags them with the upgrade command.
- M5 v2 → v3: deprecation notices already name every replacement; UPGRADING sed lines for PHP renames; `config:migrate` for config.

## Pillar 4: built for agents

Agents now read test output through wrappers such as `laravel/pao`, which keeps
failure messages verbatim and pushes everything else into a `raw[]` array.
Gesso's issue data is richer than any competitor's, but it stops before the fix.

## Owner decisions (2026-11-01)

1. **No competitor-compatible assertion facades.** Switching is mechanical instead:
   Gesso ships Rector rules that rewrite competitor calls (decision 5).
2. **Build `gesso suggest`.** It emits evidence-backed spec fixes as an OpenAPI
   Overlay and never applies them. ADR 0004's "no spec generation" non-goal is
   narrowed to "no automatic generation or application".
3. **No PHPUnit 11 / Pest 3 support.** PHPUnit 11 bug fixes ended 2026-02-06 and
   Laravel 12 security support ends 2027-02, around v3 GA. `config:migrate` and
   every migration page detect PHPUnit 11 and print the upgrade command as step 0.
4. **Match `servers[].url` path prefixes automatically**, with `spec.strip_prefixes`
   as the override. Verdict-changing, so v3 only; amends ADR 0006.
5. **Rector rules ship in the core package** (`src/Rector`, `rector/rector` in
   `suggest`), covering competitor migration (kirschbaum, Spectator, osteel, league)
   and Gesso v2 → v3 PHP renames. Custom rules are allowed; one CI lane pins the
   supported Rector range. No extra Composer package, so ADR 0007 rule 5 stands.
6. **No MCP server in v3.** Skill + CLI (JSON output, `gesso explain`). Revisit if an
   agent run with the shipped skill still fails to use `gesso`.
