# Prepare for Gesso 3.0

Gesso 3.0 removes the configuration keys, CLI spellings, and APIs that v2
deprecated. Upgrade to v2.9 first: every removal emits a
`[Gesso deprecation]` notice there, so a clean v2.9 run is a clean v3 upgrade.
The per-surface ledger lives in [`UPGRADING.md`](https://github.com/studio-design/gesso/blob/main/UPGRADING.md).

## Configuration

Since 3.0, `gesso.php` at the application root is the only configuration
entry point.

1. Generate it: `vendor/bin/gesso doctor --spec=openapi/front.json --emit-config > gesso.php`,
   or start from `php artisan vendor:publish --tag=gesso`.
2. Move every remaining value into it — the PHPUnit extension's
   `<parameter>` elements (keep only `config`, and only for a non-default
   location) and the keys of `config/gesso.php` — using the mapping table in
   [`UPGRADING.md`](https://github.com/studio-design/gesso/blob/main/UPGRADING.md#configuration).
3. Delete `config/gesso.php`, rename `config('gesso.auto_assert')`-style
   lookups and overrides in tests to the new paths
   (`config('gesso.laravel.auto_assert')`), and run `php artisan config:clear`.

A leftover parameter or flat key fails the run naming its replacement, so an
incomplete migration cannot pass silently. See
[Configuration](../configuration.md) for every key.

## CLI flags and exit codes

Each removed spelling is now a usage error (exit `2`) whose message names the
replacement, for example
`Unknown argument(s): --specs (removed in Gesso 3.0; use --spec-name)`.

| Command | Removed in 3.0 | Use instead |
| --- | --- | --- |
| `coverage:merge` | `--specs=<a,b>` | `--spec-name=<name>` (repeatable, comma-accepting) |
| `coverage:merge` | `--strip-prefixes=<a,b>` | `--strip-prefix=<prefix>` (repeatable, comma-accepting) |
| `coverage:merge` | `--json-output=<path>` | `--report=json:<path>` |
| `coverage:merge` | `--junit-output=<path>` | `--report=junit:<path>` |
| `coverage:merge` | `--html-output=<path>` | `--report=html:<path>` |
| `coverage:merge` | `--console-output=<mode>` | `--console-report=<mode>` |
| `coverage:merge` | `--min-endpoint-coverage=<pct>` | `--min-coverage="endpoint=<pct>"` |
| `coverage:merge` | `--min-response-coverage=<pct>` | `--min-coverage="response=<pct>"` |
| `coverage:merge` | `--min-sdk-exercise-coverage=<pct>` | `--min-coverage="sdk_exercise=<pct>"` |
| `coverage:merge` | `--min-coverage-strict` | `--min-coverage="strict"` |
| `coverage:merge` | `--baseline-file=<path>` | `--baseline="violations=<path>"` |
| `coverage:merge` | `--coverage-baseline-file=<path>` | `--baseline="coverage=<path>"` |
| `coverage:merge` | `--coverage-baseline-stale=<mode>` | `--baseline-stale="coverage=<mode>"` |
| `coverage:merge` | `--strict-required=<mode>` | `--strict-required="run=<mode>"` |
| `coverage:merge` | `--strict-additional-properties=<mode>` | `--strict-additional-properties="run=<mode>"` |
| `stubs`, `gesso:stubs` | `--output=<dir>` | `--output-dir=<dir>` |
| `coverage:merge` | exit `1` when a sidecar, report, or baseline file cannot be read or written | exit `2`; a check for any non-zero exit needs no change |
| `coverage:merge` | an unknown argument ignored with a `[Gesso] WARNING` | rejected with exit `2`, as `doctor`, `coverage:gate`, and `stubs` already did |

A merge with several sink or threshold flags folds into one grouped flag:
`--min-endpoint-coverage=80 --min-coverage-strict` becomes
`--min-coverage="endpoint=80,strict"`. See [the CLI reference](../cli.md#removed-flags).

## Coverage sidecars

Gesso 3.0 merges only sidecars with `envelopeVersion: 10`, the envelope every
worker has written since 2.7 (#505). The 2.x merge also read the legacy
envelopes 2–9 (written by Gesso 1.9–2.6) and the bare coverage state with no
`envelopeVersion`, with a `[Gesso deprecation]` notice since 2.9.0. The 3.0
merge rejects them, exiting `1` with a message that names the writing release
and the fix:

```text
[OpenAPI Coverage] FATAL: invalid sidecar payload: Sidecar envelope version 6
was written by a Gesso 1.9-2.6 worker; Gesso 3 reads envelopeVersion 10 only. …
```

To migrate, install the same Gesso version in the worker and merge steps,
delete any sidecar directory a v2 run left behind (for example, artifacts
restored from an earlier CI run), and re-run the parallel suite. Old sidecars
cannot be converted. See
[versioned sidecar compatibility](../versioning.md#versioned-sidecar-compatibility).

## Enum binding

Enums bind to the spec by component name only
([#508](https://github.com/studio-design/gesso/issues/508)). A backed enum
matches the `components.schemas` entry named after its class (an `Enum`
suffix on either side is ignored) in the configured specs. Keep
`#[BoundToOpenApiEnum]` only for enums whose component has another name.
These surfaces are gone:

- the file-path binding `#[BoundToOpenApiEnum('path/to/file.json')]` and the
  attribute's `$specPath` property (deprecated in 2.8.0). The attribute now
  takes one required argument, the component name; its parameter is still
  called `component`.
- `OpenApiSpecLoader::configure(enumBasePath:)` and `getEnumBasePath()`
  (deprecated in 2.8.0).
- `EnumBindingException::forBinding()` (deprecated in 2.7.0).
- the `EnumBindingReason` cases that only file-path bindings raised
  (deprecated in 2.9.0): `BasePathNotConfigured`, `EnumBasePathNotFound`,
  `EnumSpecBasePathOrphaned`, `SpecFileNotFound`, `MalformedJson`,
  `MalformedYaml`, `YamlLibraryMissing`, `NonMappingRoot`, and
  `EnumKeyMissing`. These raised no notice, so search your code for the
  names, for example an arm of a `match` over `EnumBindingReason`.

```php
// Before (v2)
#[BoundToOpenApiEnum('_shared/components/schemas/enums/IdpAuthorizeErrorCode.json')]
enum IdpErrorEnum: string { /* ... */ }
OpenApiSpecLoader::configure('openapi/bundled', enumBasePath: 'openapi');
EnumBindingException::forBinding($reason, $message, $enumFqcn);
// After (v3)
#[BoundToOpenApiEnum('IdpAuthorizeErrorCode')] // or no attribute when the names match
enum IdpErrorEnum: string { /* ... */ }
OpenApiSpecLoader::configure('openapi/bundled');
new EnumBindingException($reason, $message, $enumFqcn);
```

Enum values are now read only from the documents `OpenApiSpecLoader::load()`
returns. To keep per-enum source files, `$ref` them from `components.schemas`.
A file path left in the attribute is read as a component name and fails as
`ComponentNotFound`. The attribute with no argument fails as `AttributeInvalid`.
See [enum drift detection](../enum-drift.md#binding-by-component-name).

## Contract-check aliases

The `Studio\Gesso\Fuzz\` aliases of the named contract checks are gone
([#503](https://github.com/studio-design/gesso/issues/503); deprecated in
2.7.0). `ContractCheck`, `ContractCheckPlan`, `ContractCheckFailure`,
`ContractCheckSkip`, `ContractCheckSummary`, `OpenApiContractChecks`, and the
`@internal` `ContractCheckProbe` resolve only under `Studio\Gesso\Contract\`.
Generator types (`ExploredCase`, `OpenApiSpecExplorer`, ...) stay in
`Studio\Gesso\Fuzz\`.

```php
// Before (v2)
use Studio\Gesso\Fuzz\OpenApiContractChecks;
// After (v3)
use Studio\Gesso\Contract\OpenApiContractChecks;
```

The v2 notice did not fire for an old name referenced after the class was
already loaded, so search for `Gesso\Fuzz\ContractCheck` and
`Gesso\Fuzz\OpenApiContractChecks` rather than relying on a silent v2.9 run.

## PHPUnit dependency

`phpunit/phpunit` moved from Gesso's `require` to `require-dev`
([#506](https://github.com/studio-design/gesso/issues/506); announced in
2.9.0), so installing Gesso no longer installs a test runner. Declare
PHPUnit 12 or 13 in your own `require-dev` — a current 12.5+ or 13.x
release. Gesso's `^12.0 || ^13.0` range is unchanged: PHPUnit 11 and Pest 3
stay unsupported, and a Composer `conflict` keeps them from being installed
alongside Gesso.

```bash
composer require --dev "phpunit/phpunit:^12.5 || ^13.0"
```

A Laravel 12 application still on PHPUnit 11 or Pest 3 must upgrade the
runner first (for Pest, move to Pest 4):

```bash
composer require --dev "phpunit/phpunit:^12.5" --with-all-dependencies
```

Gesso now declares `ext-dom` (JUnit coverage report) and `ext-filter`, which
it used directly but had received through PHPUnit. Calling a Gesso assertion
without PHPUnit installed throws a `RuntimeException` naming the
`composer require` command instead of a "Class not found" fatal.

The private helpers composed into the assertion traits, deprecated in 2.9.0,
are gone: `failOpenApi()` and `assertOpenApi()` (`ValidatesOpenApiSchema`,
Symfony and PSR-7 `OpenApiAssertions`), `failPsr7()` and `assertPsr7()`
(PSR-7 `OpenApiAssertions`), and `failExplore()` (`ExploresOpenApiEndpoint`).

```php
// Before (v2)
$this->failOpenApi('message');
$this->assertOpenApi($condition, 'message');
// After (v3)
$this->fail('message');
$this->assertTrue($condition, 'message');
```

## Deprecated helper methods

`OpenApiCoverageTracker::hasAnyCoverage()` and the `SkipOpenApiResolver`
trait's private `shouldSkipOpenApi()` (composed into `ValidatesOpenApiSchema`)
are gone; both were deprecated in 2.7.0.

```php
// Before (v2)
OpenApiCoverageTracker::hasAnyCoverage('front');
$this->shouldSkipOpenApi();
// After (v3)
OpenApiCoverageTracker::current()->hasAnyCoverageOn('front');
$this->findSkipOpenApiAttribute() !== null;
```
